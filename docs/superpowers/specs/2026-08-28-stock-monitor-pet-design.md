# 股票监测桌面宠物设计规格

## 1. 产品概述

开发一个开源桌面宠物，持续监控用户选择的股票，并通过宠物气泡展示行情和提醒。Windows 是首要平台，macOS 和 Linux 共用同一套代码，通过直接下载方式分发，不进入应用商店。

默认宠物是财经小猫。用户既可以切换内置皮肤，也可以导入自己的透明静态图片或动画素材。

## 2. 第一版目标

- 支持 A 股和港股行情。
- 用户输入股票代码后，自动识别市场并展示股票名称供确认。
- 应用运行期间默认每 10 秒刷新一次全部启用股票。
- 气泡展示用户当前选中的一只股票。
- 右键点击宠物后列出全部监控股票，并能立即切换气泡股票。
- 支持涨幅、跌幅、价格上穿、价格下穿和短时快速异动提醒。
- 提供股票、提醒规则、宠物外观和常规设置界面。
- 所有配置仅保存在本机，不需要账户或云服务。
- 从同一代码仓库构建 Windows、macOS 和 Linux 安装包。

## 3. 第一版不包含

- 逐笔成交或交易所级别的实时数据。
- 券商登录、交易下单、持仓管理和收益核算。
- 手机应用、浏览器扩展和云端同步。
- App Store、Microsoft Store 或其他应用商店上架。
- 美股支持，但行情供应器接口需要保留扩展能力。

## 4. 技术方案

使用 Tauri 2、React 和 TypeScript 构建界面，使用 Rust 处理原生窗口、行情请求、提醒规则和本地状态。

选择 Tauri 的原因是桌面宠物需要长期驻留，并依赖透明窗口、窗口置顶、系统托盘、原生菜单和较低资源占用。

### 4.1 Rust 进程职责

- 每 10 秒执行一次行情轮询。
- 请求行情供应器并解析返回内容。
- 规范化股票代码并识别市场。
- 执行提醒规则和冷却时间判断。
- 持久化本地设置。
- 创建宠物窗口和设置窗口。
- 更新托盘菜单和右键菜单。
- 管理开机启动和用户导入的宠物素材。

### 4.2 React 界面职责

- 渲染宠物、行情气泡、右键菜单状态和设置页面。
- 编辑股票、提醒规则和外观设置。
- 接收 Rust 发出的行情和提醒事件。
- 预览导入素材以及不同宠物状态。

## 5. 应用窗口

### 5.1 宠物窗口

宠物窗口透明、无边框、不出现在任务栏中，并支持可选置顶。用户可以拖动宠物改变位置。

窗口只包含：

- 当前状态的猫咪素材。
- 行情或提醒气泡。
- 用于拖动、点击和打开菜单的透明交互区域。

应用记住宠物在每套显示器配置中的位置。显示器发生变化时，恢复位置必须被限制在当前可见区域内。

交互规则：

- 拖动：移动宠物。
- 左键单击：显示或隐藏当前行情气泡。
- 右键单击：打开全部监控股票菜单。
- 左键双击：打开设置窗口。

### 5.2 设置窗口

设置窗口是普通可调整大小的桌面窗口，包含四个部分：

1. 监控股票
2. 提醒规则
3. 宠物外观
4. 常规设置

用户可以从宠物右键菜单或系统托盘打开设置。关闭设置窗口只隐藏窗口，不停止行情监控。

## 6. 股票管理

添加股票时输入股票代码，名称可以由用户填写，也可以使用行情返回的名称。

代码识别规则：

- 符合交易所前缀规则的六位大陆代码识别为沪市或深市。
- 五位、补零后的代码识别为港股。
- `SH`、`SZ`、`HK` 等显式前缀优先于自动判断。
- 过短或有歧义的代码展示候选结果，不静默选择市场。

保存前必须请求一次行情，并展示解析后的股票名称、标准代码、市场和币种供用户确认。

每只股票保存以下字段：

- 本地唯一 ID
- 显示名称
- 标准股票代码
- 市场和交易所前缀
- 币种
- 是否启用
- 显示顺序
- 是否为当前气泡股票
- 关联提醒规则

用户可以添加、编辑、排序、启用、停用和删除股票。删除股票时，在确认后同时删除它的提醒规则。

## 7. 行情供应器

定义可替换的行情供应器接口，避免界面和提醒引擎依赖某个具体数据源。

接口支持：

- 将输入代码解析为一个或多个证券候选项。
- 批量获取标准股票代码的行情。
- 返回市场状态和供应器错误。

第一版默认使用腾讯公开行情接口 `https://qt.gtimg.cn/q=<symbols>`，用于小范围个人使用。沪市、深市和港股分别使用 `sh`、`sz`、`hk` 前缀。HTTP 请求由 Rust 发起以避开浏览器 CORS 限制，接口返回的 GBK 内容必须先解码再解析。

该接口不是有服务承诺的正式商业 API，因此请求、解码和解析逻辑必须隔离在单独模块中，并使用固定响应样本测试，确保未来可以整体替换。供应器错误不能被解释为价格为零，也不能触发任何提醒。

每条行情包含：

- 最新价
- 昨收价
- 涨跌额
- 涨跌幅
- 行情时间
- 可获取时的市场开闭状态
- 供应器状态

轮询服务尽量将全部启用股票合并为少量批量请求。网络或供应器失败时，重试间隔逐步增加，最长为 60 秒；界面继续显示最后一次有效行情，并明确标记为数据已过期。

## 8. 提醒规则

每只股票可以配置多条独立启用的规则：

- 涨幅达到或超过阈值。
- 跌幅达到或超过阈值。
- 价格从下方向上穿过目标价。
- 价格从上方向下穿过目标价。
- 在配置的滚动时间窗口内，价格变化达到指定百分比。

价格穿越规则只有在前一条有效行情位于目标价另一侧时才触发。涨跌幅和快速异动规则触发一次后进入冷却期，默认冷却时间为 15 分钟。

提醒触发后执行：

- 切换宠物表情或动画。
- 在气泡中展示股票、触发原因、当前价格和涨跌变化。
- 根据设置决定是否同时发送系统桌面通知。

数据过期、格式错误或不符合用户市场时段设置时，不触发提醒。

## 9. 行情气泡与右键菜单

普通行情气泡展示：

- 股票名称和标准代码
- 市场
- 最新价和币种
- 涨跌额和涨跌幅
- 最后更新时间或数据过期状态

提醒气泡额外展示触发的规则，并按用户设置的时长保持可见。

宠物右键菜单按用户排序列出全部启用股票。每行展示名称、代码、最新价和涨跌幅。点击一行后，该股票立即成为当前气泡股票。

菜单还包含：

- 显示或隐藏行情气泡
- 打开设置
- 切换窗口置顶
- 暂停或恢复监控
- 隐藏宠物到托盘
- 退出程序

系统托盘菜单提供相同的应用级操作，确保宠物隐藏后仍能恢复。

## 10. 宠物外观

内置财经小猫包含四种状态：

- 上涨：开心或兴奋
- 下跌：担心
- 横盘或空闲：休息
- 提醒：引起注意的短动画

用户可以切换内置主题，也可以为每种状态导入透明 PNG、GIF 或 APNG。导入文件会复制到应用数据目录，避免源文件移动后导致主题失效。

外观设置包括：

- 各状态素材
- 宠物大小
- 窗口透明度
- 气泡相对宠物的位置
- 是否播放动画
- 是否置顶

无效、过大或无法读取的素材会被拒绝，并显示明确错误；当前可用主题不能被破坏。

## 11. 本地状态

使用 Tauri Store 插件保存带版本号的 JSON 配置，包括股票、提醒规则、当前股票 ID、窗口位置、外观、开机启动、刷新间隔和通知设置。

快速异动规则所需的短期行情仅保存在内存中，退出程序后丢弃，不作为历史行情数据库。

第一版不需要账号、遥测或远程配置，也不需要 API 密钥。如果未来供应器需要密钥，必须使用操作系统凭据存储，不能明文写入 JSON。

## 12. 异常与边界情况

- 无网络：显示最后有效行情并标记过期，重试期间不提醒。
- 返回格式变化：拒绝异常记录，留下简洁诊断信息，程序继续运行。
- 市场休市：显示最新收盘数据和休市状态，不触发快速异动提醒。
- 系统从睡眠恢复：立即刷新一次，再恢复 10 秒轮询。
- 重复股票：定位已有记录，不新增重复项。
- 显示器移除：把宠物移回最近的可见屏幕。
- 导入素材损坏：回退到内置猫咪状态。
- 程序重复启动：恢复并聚焦已经运行的实例。

## 13. 开源与分发

代码仓库使用 MIT 许可证，并提供源码和本地构建说明。

发布文件在对应操作系统上构建：

- Windows：NSIS 安装包
- macOS：直接分发的应用包或 DMG
- Linux：AppImage 和 deb 包

小范围分发允许暂不购买代码签名证书。文档必须说明未签名 Windows 和 macOS 程序可能出现 SmartScreen 或 Gatekeeper 提示。应用商店相关要求不在范围内。

## 14. 测试策略

Rust 单元测试覆盖：

- 股票代码标准化和市场识别
- 行情供应器固定响应解析
- 价格上穿和下穿
- 涨跌幅与快速异动规则
- 冷却时间和过期数据抑制
- 配置版本迁移

集成测试使用本地模拟行情服务，覆盖批量成功、格式错误、请求超时和恢复。

React 测试覆盖：

- 添加股票和确认流程
- 当前气泡股票切换
- 提醒规则编辑与校验
- 设置保存请求
- 行情与提醒事件渲染

平台冒烟测试覆盖 Windows、macOS 和 Linux 上的透明窗口、拖动、右键菜单、托盘恢复、开机启动、导入动画播放和安装包运行。

## 15. 第一版验收标准

- Windows 用户无需开发环境即可安装并运行程序。
- 能添加有效 A 股和港股代码，并看到解析后的股票名称。
- 网络正常时，全部启用股票按 10 秒周期刷新。
- 右键点击宠物后能看到全部启用股票，并切换当前气泡。
- 涨幅、跌幅、价格穿越和快速异动规则只正确触发一次并遵守冷却期。
- 宠物隐藏到托盘后可以恢复，气泡继续可用。
- 内置猫咪状态可用，并能为各状态导入 PNG、GIF 和 APNG。
- 设置在程序重启后仍然保留。
- 网络和供应器失败不会产生错误提醒，也不会导致程序退出。
- 同一代码仓库能够生成 Windows、macOS 和 Linux 发布文件。
